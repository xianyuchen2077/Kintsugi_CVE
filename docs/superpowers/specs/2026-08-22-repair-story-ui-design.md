# 检测与修复页信息增强设计

## 目标

在不改变现有任务执行、产物读取、代码差异、白名单、验证、历史记录等功能的前提下，让“检测与修复”页更直观地回答四个问题：本次修补的整体效果、修改位置与内容、防护机制、验证证据。

页面首先使用通俗语言说明行为变化，再保留函数、文件、行号、修复方式、代码差异、白名单与验证状态等专业证据。所有结论必须来自现有运行产物，不展示无法从产物确认的攻击数量、测试数量或绝对安全结论。

## 范围与约束

- 保留现有七个主导航标题及其行为：运行总览、新建任务、运行控制台、检测与修复、白名单与验证、历史运行、最近结果。
- 仅增强现有 `DetectionRepair` 页面，不调整其他页面的业务逻辑。
- 保留历史产物选择器，并继续与运行总览、白名单与验证页共享当前选中的产物。
- 保留现有检测摘要、源码定位、修复说明和代码 Diff；原内容放入“修改详情”，不删除字段或操作。
- 不修改 Bridge API 和磁盘产物格式。新增内容只消费现有 `ArtifactDetail` 与 `HistoryRecord` 字段。
- 允许为布局、响应式显示和可访问状态增加少量 CSS，不进行全局视觉重构。
- 10 个 CVE 是固定产品范围，不增加动态 CVE 发现功能。

## 信息架构

“检测与修复”主标题保持不变。历史产物选择器下方增加四个陈述性二级入口：

1. **修补概览**：默认入口，概括漏洞行为变化、修补位置、影响范围与当前验证状态。
2. **修改详情**：承载原有检测与修复内容，包括命中排名、函数、源码路径、行号、修复说明及代码 Diff。
3. **防护机制**：用三步路径说明请求进入目标函数、修补逻辑生效、危险行为被限制的过程，并展示实际修复方式和白名单摘要。
4. **验证结果**：用完整陈述替代单独的 `Normal ✓ / Malicious ✓`，说明正常功能是否保留、恶意行为是否阻断、证据是否可复核。

二级入口使用按钮组实现，支持键盘操作和 `aria-pressed` 状态。切换只改变当前页展示区域，不触发新的后端请求，不改变已选产物。

## 内容规则

### 修补概览

- 标题保持“检测与修复”。
- 核心结论根据 `validation.normal_ok`、`validation.malicious_blocked` 和历史记录状态生成。
- 使用 `function_name`、`function_path`、`start_line`、`end_line` 标明修补位置。
- 使用 `repair_method` 生成通俗说明，同时附带专业术语。例如：
  - `network`：限制目标函数发起的网络访问；专业术语为网络过滤。
  - 其他过滤式修补：将高风险操作限制在正常业务观察到的允许范围；专业术语为运行时白名单过滤。
- 当数据不足时明确显示“产物未记录”，不补造细节。

### 修改详情

- 复用现有检测摘要、修复说明、修复指标、源码位置和代码 Diff。
- 保持原始代码与修复代码的行号、增删统计和语法高亮逻辑。
- 在专业代码下增加一段基于现有字段的简洁解释，不替换原始 `analysis`。

### 防护机制

- 用三步结构展示：进入目标函数 → 修补逻辑生效 → 验证观察到的结果。
- 展示 `repair_method`、`syscall_rules` 和规则数量；原始规则最多显示摘要，完整规则仍由“白名单与验证”页负责。
- 不把所有修补方式都描述成 eBPF；文本随 `repair_method` 调整。

### 验证结果

- 将正常验证和恶意验证分别写成完整结论：正常业务保持可用、恶意行为被阻断、未通过或尚无证据。
- 展示总尝试次数、产物目录和日志尾部，沿用现有数据刷新机制。
- 成功只表述为“本次验证通过”或“已覆盖用例通过”，不表述为“漏洞绝对安全”。

## 数据流

1. `useArtifactView` 继续加载历史产物和 `artifact-detail`。
2. `DetectionRepair` 从已加载的 `detail` 与 `selected` 记录派生四个视图需要的文案和状态。
3. 二级入口只维护本地视图状态；切换时不重新获取数据。
4. 现有五秒产物刷新与跨页面产物选择保持不变。

## 空状态与异常状态

- 没有历史产物时，保留现有空状态，不显示无依据的修补故事。
- 产物存在但代码缺失时，“修改详情”显示原有“暂无修复代码”状态，其余入口继续展示可确认的字段。
- 验证字段缺失时显示“尚无验证证据”，不得将缺失值解释为失败或通过。
- 网络读取失败时沿用当前最近一次有效产物，不新增会阻断页面使用的错误弹窗。

## 样式与响应式

- 二级入口位于产物选择器与内容主体之间，视觉层级低于七个主导航。
- 桌面端可横向排列；窄屏自动换行，不产生页面级横向滚动。
- 复用现有颜色、圆角、间距和暗色模式变量，新增类名限定在检测与修复区域。
- 代码 Diff 在桌面端保持原布局，移动端沿用现有响应式策略。

## 验证计划

- 为修补说明派生函数增加单元测试，覆盖成功、验证失败、字段缺失、网络修补和过滤式修补。
- 构建前端，确认 TypeScript 与产物生成成功。
- 运行现有渲染测试，确认主页面仍可正常渲染。
- 检查四个二级入口可切换且原有“修改详情”内容完整存在。
- 在桌面和移动宽度下检查主导航未改名、二级入口自动换行、代码区域无异常溢出。

## 非目标

- 不新增或删除 CVE。
- 不重构全局导航、Bridge 队列、任务执行或历史删除逻辑。
- 不改变产物 JSON 格式。
- 不在本次改动中接入 SSE、持久化任务队列或重构整个 `page.tsx`。
