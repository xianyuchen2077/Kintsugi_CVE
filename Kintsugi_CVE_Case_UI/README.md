# KINTSUGI Case UI

独立的本地案例展示界面，沿用页眉导航，按“演示流程、漏洞定位、修补解析、结果对比”展示已有实验资料。

- Cacti：请求来源、命令边界和文件副作用。
- Ghostscript（重点案例）：图片内容识别、容器观察窗，以及正常／恶意／修补后恶意流量对照。
- VuFind：SSRF 请求与内部网络访问路径。

## 运行

需要 Node.js 22.13 或更高版本。在本目录执行：

```bash
npm install
npm run dev
```

访问终端显示的本地地址。开发预览通常使用 http://localhost:3000/；端口被占用时以终端输出为准。

## 第二个案例的演示方式

1. 选择 CVE-2018-16509，打开“漏洞定位”。
2. 点击“正常样本”“恶意样本”或“修补后恶意样本”，逐步观察输入内容与容器文件变化。也可选择本地文件。
3. 点击“查看文件内部”，检查真实文件头与 %pipe% 操作符。
4. 点击观察窗中的 got_rce 文件区域，查看证据来源及限制。
5. 打开“修补解析”查看代码与解释；打开“结果对比”，用“演示本页”同步展示三种流量，或单独播放每一列。

内置样本位于 `public/case-samples/CVE-2018-16509/`。恶意样本仅用于授权隔离实验；界面读取其字节，不在浏览器里执行载荷。

## 数据与运行边界

当前页面不是实时 Docker 控制台，也不会运行真实攻击、修补或环境重置。重置按钮只清空展示状态。文件选择后在浏览器读取内容，匹配已准备好的演示路径。

Ghostscript 的 HTTP 200 / 1653 bytes、恶意 HTTP 500 / 标记未创建等信息来自既有报告，汇总在 `app/cve-2018-report-data.mjs`。Stage 10 最终验证采用 Python 输入检查，不应表述为已验证的内核 eBPF 拦截。

修补前标记文件出现、正常目录状态和程序关系中缺乏原始观测记录的部分标为原理示意；不伪造时间戳、PID、系统调用计数或返回图片。详见 `docs/ghostscript-observer.md`。

## 保留的接口适配层

`app/case-gateway.mjs` 保留模拟流程和本地 Bridge 适配器，当前展示页未调用该适配器。未来接入需单独验证，不代表界面现已实时连接。

预留案例接口：`POST /api/cases/:cve/attack`、`POST /api/cases/:cve/repair`、`POST /api/cases/:cve/reset`、`GET /api/cases/:cve/events`。

Bridge 适配器使用健康检查、运行前检查、任务提交和事件流接口；详情以适配器代码与测试为准。不要把 Docker 控制接口或实验服务暴露到公网。
